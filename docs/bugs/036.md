# Bug 36 — Leak of buf_with_nul on u_strToUTF8 failure in transliterateString

**File:** `src/tokenizer.zig` (`transliterateString`, ~206–212)
**Severity:** LOW (memory leak on error path)

## Description

In `transliterateString`, `buf_with_nul` is allocated on the heap (`allocator.alloc(u8, @as(usize, @intCast(utf8_len)) + 1)`) without an accompanying `errdefer` or explicit `free` before checking the status of `icu.u_strToUTF8`:

```zig
const buf_with_nul = try allocator.alloc(u8, @as(usize, @intCast(utf8_len)) + 1);

_ = icu.u_strToUTF8(buf_with_nul.ptr, utf8_len + 1, null, output_u16.ptr, limit, &status);
if (c.U_FAILURE(status)) {
    return error.Utf8ConvertFailed;
}
```

If `u_strToUTF8` returns a failure status, `transliterateString` returns `error.Utf8ConvertFailed` while leaking `buf_with_nul`.

## Impact

- Heap memory leak of `utf8_len + 1` bytes whenever the final `u_strToUTF8` conversion call fails.

## Suggested fix

Free `buf_with_nul` (`allocator.free(buf_with_nul);`) before returning `error.Utf8ConvertFailed`.

## Implemented

Added `allocator.free(buf_with_nul);` in the `if (c.U_FAILURE(status))` error branch in `src/tokenizer.zig` (committed in `82d966615cc5`) and verified across both Zig 0.16.0 and Zig 0.17.0.

**Status:** ✅ FIXED.
