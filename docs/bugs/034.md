# Bug 34 — Unfactored duplication across tokenizer, resolvers, and build

**Severity:** LOW (style)

## Description

No runtime effect; each item raises the review surface for the next audit:

- **Rule-string sniffing:** `"Russian-Latin/BGN"` probed 3×
  (`transliterateString` incl. its retry branch, plus `tokenizeText`) and
  Arabic/Hebrew probed 2× (`src/tokenizer.zig` ~92, ~115, ~153, ~377–379).
  Should be boolean flags on `LocaleInfo` computed once (previously noted
  in [minor notes](minor-notes.md), now formally filed).
- **Decode loops:** `buildByteOffsetMap` vs
  `convertUtf8ToUtf16Tolerant` share the same codepoint-walk; the tolerant
  converter could fill the map in the one place it is needed.
- **Grow blocks:** three grow-on-overflow shapes (`transliterateString`
  retry, pre-translit retry, `destBuf` double-grow) — one helper.
- **Resolvers:** 12 near-identical blocks in `src/c_icu.zig` differing only
  in symbol name — generatable from a comptime name table.
- **Wrappers:** `icuTokenizeV1`/`icuTokenizeV2` differ only in locale
  plumbing — one inner function.
- **Constants/paths:** `ICU_RULE_TH` ≡ `ICU_RULE_KO` (comment why, or
  share); system include/library path blocks repeated 3× in `build.zig`.
- **Extra copy:** `transliterateString` returns `allocator.dupe` of its
  internal buffer — one avoidable alloc+copy per call.

## Impact

- Maintenance burden only; each duplication is a future-drift risk of the
  [Bug 6](006.md) class.

## Suggested fix

Factor in small, test-neutral refactors (no behavior change; suite must
stay green throughout).

**Status:** OPEN.
