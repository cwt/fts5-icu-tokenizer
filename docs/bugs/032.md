# Bug 32 — getFts5Api ignores bind/step return codes

**File:** `src/fts5_icu.zig` (`getFts5Api`)
**Severity:** LOW (style/robustness)

## Description

`bind_pointer` and `step` return values are discarded (`_ =`). The outcome
is safe (a null API pointer funnels into the existing error path), but a
failed bind vs. a genuinely missing FTS5 are indistinguishable, and a
`step` that returns no row is not distinguished from an error either.

## Impact

- No runtime defect; poorer diagnostics when extension loading fails.

## Suggested fix

Check `bind_pointer` (return null on failure) and require `step` to report
a row before accepting `pFts5Api`; keep the existing error message.

**Status:** OPEN.
