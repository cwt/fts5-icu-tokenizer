# Bug 38 — Signed i32 arithmetic overflow on buffer growth calculations

**File:** `src/tokenizer.zig` (`transliterateString` ~173–208, `tokenizeText` ~628–642, ~771–782)
**Severity:** MEDIUM (integer overflow / safety panic or wrap)

## Description

Although [Bug 27](027.md) capped input `text.len` at `max_text_len` (128 MiB), multi-character expansions (such as ligature decompositions or custom rules like `Any-Name`) can expand `out_len`, `tlen`, or `utf8_len` beyond the initial `3x` heuristic:

1. In `tokenizeText` (~772):
   ```zig
   const newDestSize: usize = @intCast(utf8_len + 64);
   ```
   `utf8_len + 64` is computed in signed `i32` before casting to `usize`, whereas lines 173 and 628 widen first (`@as(usize, @intCast(out_len)) + 64`). If `utf8_len > std.math.maxInt(i32) - 64`, signed `i32` addition overflows (panic in Debug, wrap in ReleaseFast).
2. In `transliterateString` (~208):
   ```zig
   _ = icu.u_strToUTF8(buf_with_nul.ptr, utf8_len + 1, null, output_u16.ptr, limit, &status);
   ```
   `utf8_len + 1` is computed in `i32`, and in the retry loops (~184, ~642, ~782) `@intCast(need)` / `@intCast(destBuf.len)` casts `usize` back to `i32` without verifying `need <= std.math.maxInt(i32)`.

## Impact

- Inputs whose transliterated representation approaches `std.math.maxInt(i32)` can trigger an unchecked `@intCast` or signed `i32` addition overflow (CWE-190).

## Suggested fix

- Widen to `usize` before adding headroom (`const newDestSize: usize = @as(usize, @intCast(utf8_len)) + 64;`).
- Guard grown buffer capacities against `std.math.maxInt(i32)` before passing `@intCast` lengths into ICU C functions, returning `error.TextTooLarge` / `c.SQLITE_TOOBIG` if exceeded.

**Status:** OPEN.
