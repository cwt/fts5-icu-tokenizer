# Bug 37 — Memory leak in tokenizeText pre-transliteration retry loop when use_stack is true

**File:** `src/tokenizer.zig` (`tokenizeText`, ~608–635)
**Severity:** HIGH (memory leak on multi-step buffer growth)

## Description

In `tokenizeText`, the pre-transliteration block computes `const use_stack = req_norm_cap <= STACK_CAP * 3;` once before entering the `while (ts == c.U_BUFFER_OVERFLOW_ERROR and norm_retries < max_translit_retries)` loop:

```zig
const use_stack = req_norm_cap <= STACK_CAP * 3;
...
while (ts == c.U_BUFFER_OVERFLOW_ERROR and norm_retries < max_translit_retries) : (norm_retries += 1) {
    const need: usize = @as(usize, @intCast(tlen)) + 64;
    if (use_stack) {
        heap_norm = try allocator.alloc(c.UChar, need);
        cur_norm = heap_norm.?;
    } else {
        heap_norm = try allocator.realloc(heap_norm.?, need);
        cur_norm = heap_norm.?;
    }
```

Because `use_stack` is a `const` boolean, if an input starts on the stack (`use_stack == true`), overflows on iteration 0 (allocating `heap_norm`), and overflows a second time on iteration 1, `if (use_stack)` is still `true`. Iteration 1 calls `allocator.alloc` again and overwrites `heap_norm` without freeing the buffer allocated on iteration 0.

By contrast, `destBuf` (~759–779) correctly checks `if (heap_dest) |hd|` to decide between `realloc` and initial `alloc`.

## Impact

- Any multi-step overflow starting from the stack buffer leaks every intermediate `heap_norm` allocation.

## Suggested fix

Check `if (heap_norm) |hn|` instead of `if (use_stack)`:

```zig
if (heap_norm) |hn| {
    heap_norm = try allocator.realloc(hn, need);
} else {
    heap_norm = try allocator.alloc(c.UChar, need);
}
cur_norm = heap_norm.?;
```

**Status:** OPEN.
