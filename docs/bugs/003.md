# Bug 3 — transliterateString errors instead of growing on overflow

**File:** `src/tokenizer.zig`
**Severity:** MEDIUM

## Description

```zig
const capacity = input_u16.len * 3 + 64;
...
if (c.U_FAILURE(status)) {
    return error.TransliterateFailed; // <-- fails on overflow
}
```

Any input whose transliteration needed more than `3× + 64` UTF-16 units
failed instead of growing the buffer. Same bug class as [Bug 2](002.md),
but on the standalone `transliterateString` helper used by the
`test_transliterator`, `locale_specific_tests`, and `test_locale_tokenizer`
executables (not the FTS5 query path).

## Impact

- Incorrect output / hard failure for heavily expanding transliterations
  (e.g. heavy `NFKD` decompositions) in helper callers.

## Fix

Loop-and-grow on `U_BUFFER_OVERFLOW_ERROR`, using the ICU-reported length to
size the next attempt. No std equivalent exists for the ICU output buffer.

**Status:** ✅ FIXED — e5d548a2.
