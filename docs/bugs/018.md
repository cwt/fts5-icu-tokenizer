# Bug 18 — Arabic/Hebrew tokens retain non-ASCII modifier letters

**File:** `src/tokenizer.zig`
**Severity:** LOW

## Description

`Arabic-Latin` emits U+02BF (ʿ) and `Hebrew-Latin` can emit U+02BB (ʻ) /
U+2019 (ʼ); `Latin-ASCII` maps only letters, digits, and basic punctuation,
so the modifiers survived. Probed on ICU 78 and 67.1.0: العربية →
`alʿrbyt` (bytes `CA BF`).

## Impact

- Arabic tokens not pure ASCII: ASCII queries and URL-safe token handling
  behaved inconsistently; modifiers had to be typed exactly.

## Fix

Strip U+02BF/U+02BB/U+2019 in the UTF-8 domain (`stripTranslitMarks`),
applied to token text in `tokenizeText` and to `transliterateString`
results, gated on the rule string. Only token *text* is compacted — byte
ranges and whitespace are untouched, so the position map ([Bug 15](015.md))
holds. E.g. العربية → `alrbyt`, قرآن → `qran`.
