# Bug 1 — Transliterator shared across threads

**File:** `src/tokenizer.zig`
**Severity:** HIGH

## Description

`tokenizeText` cloned only the break iterator for per-call thread safety, but
reused the **single shared** transliterator owned by the `IcuTokenizer`:

```zig
var baseBreakIterator = tokenizer.pBreakIterator.?;   // cloned per call
var pTransliterator    = tokenizer.pTransliterator.?; // shared! <-- race
```

ICU's `UTransliterator` is **not thread-safe** — concurrent
`utrans_transUChars` calls on one object are a data race. An earlier commit
fixed only the break iterator, leaving the transliterator shared. The
concurrent unit test passed only by luck (races are heisenbugs).

## Impact

- Intermittent token corruption or crashes under concurrent indexing/querying
  with a shared tokenizer. Silent and hard to reproduce.

## Fix

Clone the transliterator per `tokenizeText` call via ICU's `utrans_clone`
(resolver added to `src/c_icu.zig`, mirroring the other resolvers) and close
it in the same `defer` block as the break iterator:

```zig
var trans_status: c.UErrorCode = c.U_ZERO_ERROR;
const pTransliterator = icu.utrans_clone(tokenizer.pTransliterator.?, &trans_status);
if (c.U_FAILURE(trans_status) or pTransliterator == null) return c.SQLITE_ERROR;
defer icu.utrans_close(pTransliterator);
```

**Status:** ✅ FIXED — 8925a336. No Zig 0.16 std replacement exists; this is
an ICU threading contract, fixed with the ICU built-in primitive.
