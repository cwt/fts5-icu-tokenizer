# Bug 21 — getLocaleInfo matching case-sensitive and unanchored

**File:** `src/rules.zig`
**Severity:** LOW

## Description

Two defects in one matcher:

1. **Case-sensitive:** `"JA"` etc. missed the alias table and fell to
   DEFAULT + tokenizer name `"icu"`, while `isValidLocaleLanguage`
   accepted them (ICU IDs are case-insensitive).
2. **Unanchored:** raw 2-byte prefixes hijacked unrelated languages:
   `kok` (Konkani) → ko, `arn` (Mapudungun) → ar, `jam` (Jamaican Creole)
   → ja.

Blast radius was small only because `ICU_RULE_DEFAULT` happens to be a
superset of every per-locale chain — incidental coupling, not design.

## Impact

- Inconsistent rule selection between equivalent spellings; wrong
  tokenizer name for uppercase locales; latent breakage if per-locale
  chains ever diverge from DEFAULT.

## Fix

Extract the full language subtag (up to `-`/`_`/`@`) and compare
case-insensitively via a `langEql` helper; alias table unchanged.

**Status:** ✅ FIXED.
