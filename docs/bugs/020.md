# Bug 20 — Query-time override_locale bypassed locale validation

**File:** `src/tokenizer.zig`
**Severity:** MEDIUM

## Description

[Bug 16](016.md) added `isValidLocaleLanguage` to `IcuTokenizer.create`,
but the v2 per-call override path fed `pLocale` straight into
`ubrk_open`/`utrans_openU` unvalidated. Probed: `"xx_NOPE"` returned
`SQLITE_OK` and tokenized with the universal chain at query time, while the
identical string failed at create time — contradictory contracts for the
same input.

## Impact

- Typo'd row/query-time locales silently accepted; hard-to-debug wrong
  results instead of an error.

## Fix

Run the existing `isValidLocaleLanguage` on the override before opening
the dynamic iterator/transliterator (reuse, don't duplicate); return
`SQLITE_ERROR` on rejection. Valid overrides and the empty override are
unaffected.

**Status:** ✅ FIXED.
