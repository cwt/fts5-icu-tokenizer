# Bug 8 — Double-free in transliterateString on OOM during growth

**File:** `src/tokenizer.zig`
**Severity:** MEDIUM

## Description

On `U_BUFFER_OVERFLOW_ERROR` the old buffer was freed **before** the
replacement allocation:

```zig
allocator.free(output_u16);                  // frees first alloc
output_u16 = try allocator.alloc(c.UChar, need); // if this fails...
```

Zig `defer` captures variables by reference, so on `OutOfMemory`
`output_u16` still held the freed pointer and the scope-exit
`defer allocator.free(output_u16)` double-freed it (CWE-415). Triggered
only when expansion exceeded `3× + 64` units **and** the system was under
memory pressure — rare but real heap corruption.

## Impact

- Heap corruption on an OOM path; allocator state undefined afterwards.

## Fix

Allocate into a temporary first, then swap — a failed `alloc` leaves
`output_u16` pointing at the still-valid original buffer, which `defer`
frees exactly once:

```zig
const new_u16 = try allocator.alloc(c.UChar, need); // allocate first
allocator.free(output_u16);                          // then free the old one
output_u16 = new_u16;
```

Guarded by the `transliterateString overflow retry` regression test, which
forces the retry branch with an `Any-Name` transform.
