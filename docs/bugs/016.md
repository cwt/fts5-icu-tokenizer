# Bug 16 — Invalid locale silently accepted via root fallback

**File:** `src/tokenizer.zig` (`IcuTokenizer.create`)
**Severity:** LOW

## Description

`ubrk_open` returns `U_USING_FALLBACK_WARNING` for unresolvable locales
(e.g. `"xx_YY"`), which `U_FAILURE` does not catch — so creation succeeded
with root rules. Worse, probes showed the warning fires for **every**
non-empty locale (`ja`, `ru_RU`, `en_US` included, since word-break data
lives in root), so the status code cannot distinguish typos from valid
locales at all.

## Impact

- Locale typos in `CREATE VIRTUAL TABLE` silently fell back to root
  segmentation: hard-to-debug wrong results instead of an error.

## Fix

Validate the locale **string** at create time (`isValidLocaleLanguage`):
empty locale, `"C"`/`"POSIX"`, any `rules.zig` alias language, or a
language in `uloc_getAvailable` (language extracted via
`uloc_getLanguage`, so `en_US.UTF-8` → `en` works). Rejected locales fail
with `error.IcuInvalidLocale` → `SQLITE_ERROR`.
