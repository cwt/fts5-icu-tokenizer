# Bug 2 — Silent token drop on transliteration buffer overflow

**File:** `src/tokenizer.zig`
**Severity:** MEDIUM

## Description

`transBuf` was sized with a fixed heuristic (`nSrc * 6 + 2048`) and never
grown. If a token's transliteration expanded beyond it,
`utrans_transUChars` returned `U_BUFFER_OVERFLOW_ERROR`, `U_FAILURE` was
true, and the token was skipped with `continue` — no error to SQLite, the
word simply absent from the index.

## Impact

- Words that expand significantly under transliteration missing from search
  results, with no diagnostic. Affects real queries, not just tests.

## Fix

Grow `transBuf` to the required length on `U_BUFFER_OVERFLOW_ERROR` and
retry, mirroring the `destBuf` grow logic. There is no Zig 0.16 std
replacement for the raw ICU intermediate buffer (`std.BoundedArray` does not
exist in 0.16.0, so the custom stack/heap SBO buffers stay).

**Status:** ✅ FIXED — 2e4e44a7.
