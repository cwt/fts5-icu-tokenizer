# Bug 15 — Whole-string proportional position map skews offsets, drops tokens

**File:** `src/tokenizer.zig`
**Severity:** HIGH

## Description

The normalized→original position map used whole-string proportional
scaling, exact only for 1:1 transliterations. Any expansion (ﬁ→fi 1→2
units, щ→shch 1→5) compressed **every** later position: wrong byte ranges,
and colliding mapped positions made `nTokenByte <= 0` silently drop tokens.
Empirically `a ﬁ b` yielded `fi` at `[1,5)` instead of `[2,5)`, with the
`a` token dropped entirely.

## Impact

- Wrong FTS5 snippet/highlight offsets and silently lost searchable tokens
  whenever an expansion precedes the match.

## Fix

Anchor the map at whitespace — every rule chain preserves whitespace 1:1
(probed: NFKD maps NBSP, U+2000..U+200A, U+202F, U+205F, U+3000 to U+0020;
ZWSP, LS, PS, U+1680 never anchor). Whitespace pairs exactly; segments
between anchors scale proportionally with round-half-up. Verified exact
for `a ﬁ b` and `борщ вкусный` (including the 1→5 щ expansion).

**Status:** ✅ FIXED — 05c52e983470.
