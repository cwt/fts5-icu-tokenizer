# Bug 7 — utf8ToUtf16Alloc reinvented UTF-8 to UTF-16 via ICU

**File:** `src/tokenizer.zig`
**Severity:** LOW

## Description

`utf8ToUtf16Alloc` used a two-pass manual probe through ICU's
`u_strFromUTF8` (call once with zero-length destination to learn the
length, then `allocSentinel` and fill). Zig 0.16 std provides this as a
single call returning `[:0]u16`, identical to `[:0]c.UChar`, so all callers
(`utrans_openU(rules_u16.ptr, -1, ...)` in `create` and
`transliterateString`) are unchanged.

## Impact

- No correctness defect, but avoidable complexity plus an extra ICU
  dependency. Behavior note: ICU substitutes `U+FFFD` on malformed input
  while the std converter returns `error.InvalidUtf8` — moot for the
  always-valid rule/locale strings.

## Fix

```zig
pub fn utf8ToUtf16Alloc(allocator: std.mem.Allocator, text: []const u8) ![:0]c.UChar {
    return std.unicode.utf8ToUtf16LeAllocZ(allocator, text);
}
```

Little-endian matches ICU's native-endian `UChar` on the supported
little-endian targets (x86_64 / ARM64, macOS & Linux).
