# Bug 10 — u_strToUTF8 buffer one byte too small (heap overflow)

**File:** `src/tokenizer.zig` (`transliterateString`)
**Severity:** LOW

## Description

ICU's `u_strToUTF8` preflight returns the content length **without** the NUL
(verified empirically: `"abc"` → 3), but the buffer was allocated with
`utf8_len` bytes while passing `destCapacity = utf8_len + 1`. ICU therefore
wrote the NUL terminator one byte past the allocation (CWE-787) on every
successful conversion.

> Diagnosis correction: an early draft claimed the preflight length
> *included* the NUL and proposed `destCapacity = utf8_len` — wrong, since
> that leaves no room for the NUL and ICU returns
> `U_BUFFER_OVERFLOW_ERROR`. The buffer must grow to `utf8_len + 1`.

## Impact

- 1-byte out-of-bounds write per call; silent today but undefined behavior
  that can corrupt adjacent heap metadata (the testing allocator's canary
  caught the original during development).

## Fix

Allocate `utf8_len + 1` and pass `destCapacity = utf8_len + 1`; return an
exact `utf8_len`-byte copy so the caller can free it normally.
