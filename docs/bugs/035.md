# Bug 35 — 16-byte language buffer rejects long language subtags

**File:** `src/tokenizer.zig` (`isValidLocaleLanguage`)
**Severity:** LOW (edge case)

## Description

The language scratch buffer is `[16]u8`; any locale whose language subtag
exceeds 16 bytes is rejected as `IcuInvalidLocale`, even if ICU would
resolve it. BCP47 primary language subtags run 2–8 characters, so nothing
real hits this today — but the failure mode (valid locale rejected at
`CREATE TABLE`) is indistinguishable from a typo.

## Impact

- Exotic-but-valid locales fail closed with a misleading error class.

## Suggested fix

Size the buffer for the BCP47 maximum (or heap-allocate via
`uloc_getLanguage` preflight) and cover with a long-subtag acceptance
test alongside the existing [Bug 16](016.md) cases.

**Status:** OPEN.
