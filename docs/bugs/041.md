# Bug 41 — isValidLocaleLanguage misses regional-only ICU locales and redundant orig_space_total scan

**File:** `src/tokenizer.zig` (`isValidLocaleLanguage` ~347–373, `tokenizeText` ~674–706)
**Severity:** LOW (algorithmic edge case & micro-optimization)

## Description

1. **Regional-only locale entries in `isValidLocaleLanguage` (~367–372):**
   `uloc_getLanguage` extracts only the primary language subtag `lang` (e.g., `"kok"`, `"en"`), and the loop then compares `lang` for exact equality against `std.mem.span(icu.uloc_getAvailable(i))`:
   ```zig
   while (i < count) : (i += 1) {
       if (std.mem.eql(u8, lang, std.mem.span(icu.uloc_getAvailable(i)))) return true;
   }
   ```
   `uloc_getAvailable(i)` returns locale identifiers such as `"en_US"`, `"zh_Hans_CN"`, etc. If an ICU build only lists regional variants for a language (e.g., `"kok_IN"`) without a bare language-only entry (`"kok"`), exact equality against `uloc_getAvailable(i)` fails even though ICU supports that language. Matching the language prefix of `uloc_getAvailable(i)` up to `'_'` or `'-'` (plus adding `"en"` to the fast-path alias check) resolves both the edge case and the linear C-call scan for English.

2. **Redundant `orig_space_total` scan when `norm_space_total == 0` (~674–686):**
   In `tokenizeText`, `utf16_text_buffer[0..utf16_pos]` is scanned to count `orig_space_total` even when `norm_space_total == 0`. When `norm_space_total == 0` (common for single words and CJK queries), `phantom_spaces` is `0` and the whitespace-anchoring loop does zero iterations, so counting `orig_space_total` is dead work.

## Impact

- Locales present in ICU only under regional tags are falsely rejected as `IcuInvalidLocale`, and single-token/space-free inputs pay an unnecessary UTF-16 scan.

## Suggested fix

- Match the language subtag prefix of `uloc_getAvailable(i)` (up to end-of-string, `'_'`, or `'-'`) and include `"en"` in the fast-path check.
- Skip counting `orig_space_total` and the anchor loop when `norm_space_total == 0`.

**Status:** OPEN.
