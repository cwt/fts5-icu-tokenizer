# Bug 4 — Edge-case UTF-16 truncation of the final character

**File:** `src/tokenizer.zig`
**Severity:** LOW

## Description

`tokenizeText` converted input with a hand-rolled loop (std only for
decoding, manual surrogate-pair math for encoding). The buffer was sized
`text.len + 1` and a 4-byte code point was dropped when only one `UChar`
slot remained:

```zig
if (cp > 0xFFFF) {
    if (utf16_pos + 2 > utf16_text_buffer.len) break; // drops trailing pair
}
```

UTF-16 can be up to 2× the UTF-8 length, so this only bit when the total
UTF-16 length exactly equalled `text.len` **and** the final code point was a
surrogate pair.

## Impact

- Extremely rare off-by-one in byte-offset mapping for a trailing
  emoji/surrogate pair. No crash, minimal real-world effect.

## Fix

Replaced the reinvented encoder with Zig 0.16's
`std.unicode.utf8ToUtf16Le`, with buffers sized `2 * text.len + 1` (the
converter assumes sufficient space) and a separate pass building the
byte-offset map. Malformed input still falls back to the tolerant converter
(`std` returns `error.InvalidUtf8` instead of substituting `U+FFFD`).

**Status:** ✅ FIXED — d14c914a.
