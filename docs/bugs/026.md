# Bug 26 — Per-row full ICU open on the query-time override path

**File:** `src/tokenizer.zig` (`tokenizeText`, override branch ~391–420)
**Severity:** MEDIUM (performance)

## Description

When `override_locale` is present, **every** `xTokenize` call — i.e. every
indexed row — performs `dupeZ` + a full `isValidLocaleLanguage` scan of
`uloc_getAvailable` + `utf8ToUtf16Alloc(rules)` + `ubrk_open` +
`utrans_openU`, then closes both handles. `utrans_openU` parses and
compiles the compound transliterator from the rule string each time, which
is orders of magnitude heavier than the clone-per-call fast path used
without an override. The same call also runs `getRulesForLocale` 3× plus
two full rule-string scans (~377–379) to derive flags that could be
computed once.

## Impact

- Indexing N rows with a query-time locale override pays full ICU
  setup/teardown N times. On large tables this dominates tokenization
  cost.

## Suggested fix

Cache compiled per-locale objects (break-iterator prototype +
transliterator prototype, then clone per call as today) behind a
mutex-guarded map, or at minimum cache the validation verdict per locale
string. Keep the [Bug 20](020.md) validation semantics unchanged.

## Implemented

Single-entry per-locale cache on `IcuTokenizer` (`cached_locale` +
handles, allocated with the create-time allocator). Overrides equal to the
tokenizer's own locale (or empty) use the base handles with no locking;
differing overrides lock once: hits borrow cached handles, misses validate
+ open fresh + install. Borrow and both per-call clones happen under the
lock so a concurrent evict cannot close handles mid-clone; the lock
releases before the token loop so `xToken` callbacks run unlocked. The
lock is a small atomics-based spin-yield mutex (`CacheMutex`) because
`std.Io.Mutex` needs an `io` handle the FTS5 C callbacks cannot provide
(`std.Thread.Mutex` no longer exists in 0.16). Guarded by miss/hit/evict
identity tests and a mixed-override concurrency test.

**Status:** ✅ FIXED.
