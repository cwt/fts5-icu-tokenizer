# Bug 19 — NFKD ligature expansion corrupts the token stream

**File:** `src/tokenizer.zig`
**Severity:** HIGH

## Description

The [Bug 15](015.md) fix assumed every rule chain preserves whitespace 1:1.
False for compatibility characters whose NFKD decomposition **inserts**
spaces: U+FDFA (ﷺ) expands 1 unit into 19 units containing **three real
U+0020**. The first phantom space stole the input's real space; later ones
scanned to end-of-text; the trailing segment scaled onto a zero-length span.
Probed on ICU 78 with `xﷺy z` (universal tokenizer):

```text
norm = 'xsly allh ʿlyh wsllmy z'
token='xsly' [0,5)  <- franken-token glued onto 'x'
token='lyh'  [6,7)  <- claims bytes of 'z'
```

`allh`, `ʿlyh`, `wsllmy`, the real `y` and `z` were silently dropped.

## Impact

- Index asserts content that does not exist; real words lost. Silent index
  corruption on any text with decompose-into-whitespace ligatures.

## Fix

Count space-like units on both sides; the surplus (`phantom_spaces`) is
skipped as ordinary characters while the rest pair **from the END**
(inserted whitespace clusters inside expanded content; structural sentence
whitespace aligns terminally). Segment scaling moved into `fillSegment`,
which pins degenerate zero-length spans to their boundary. Post-fix ranges
are monotonic and in-bounds; the final word survives. Words entirely inside
expanded ligature content may still collapse to zero-width and drop —
unrecoverable — but can no longer claim foreign bytes.

**Status:** ✅ FIXED.
