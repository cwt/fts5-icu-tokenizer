# Bug 28 — ICU_RULE_DEFAULT pipeline order diverges from JA/ZH

**File:** `src/rules.zig` (`ICU_RULE_DEFAULT` vs `ICU_RULE_JA`/`ICU_RULE_ZH`)
**Severity:** LOW (logic)

## Description

JA/ZH convert first and normalize after:

```text
NFKD; Hiragana-Katakana; Lower; NFKC
```

but DEFAULT normalizes **before** converting, with no trailing pass:

```text
NFKD; ...; Latin-ASCII; Lower; NFKC; Traditional-Simplified; Hiragana-Katakana
```

The same Japanese/Chinese text therefore flows through different pipelines
via the universal vs. locale-specific libraries and can yield different
token bytes. Likely harmless for CJK (no case), but the divergence is
unintended, and the converted output never sees a final NFKC.

## Impact

- Universal vs locale tokenizers can disagree on token forms for the same
  text; latent normalization gap for conversion output.

## Suggested fix

Either append the trailing `Lower; NFKC` to DEFAULT or document why the
orders intentionally differ, with a test asserting universal-vs-locale
token agreement on shared inputs.

**Status:** OPEN.
