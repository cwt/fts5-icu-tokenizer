# Bug 6 — Duplicated init paths, entrypoints, and resolver fallbacks

**Files:** `src/fts5_icu.zig`, `src/c_icu.zig`
**Severity:** LOW (style)

## Description

- `initExtensionForLocaleV1` / `initExtensionForLocaleV2` were ~90%
  identical (only the `iVersion < 3` guard and which
  `xCreateTokenizer(_v2)` is called differed).
- 18 `sqlite3_ftsicu*[_legacy]_init` entrypoints were mechanical
  repetitions; alias pairs like `sqlite3_ftsicuja_init` /
  `sqlite3_ftsicu_ja_init` are pure aliases.
- Every resolver in `src/c_icu.zig` ended with an unreachable
  `else @field(c, ...)` branch (a missing symbol is a compile-time error,
  so the `else` could never execute).

## Impact

- No runtime effect; larger review surface and drift risk between V1/V2.

## Fix

Merged the init functions behind a version parameter and emitted the
entrypoints from a single `comptime` table (a Zig language built-in),
keeping exported symbol names byte-for-byte identical. Guarded by the
entrypoint-table-integrity unit test.

**Status:** ✅ FIXED — c9ac710e.
